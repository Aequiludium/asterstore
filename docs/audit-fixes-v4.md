# v4 审计修复记录

2026-09-26。修复基于主审与独立编码模型交叉复现的四项问题及一个协议一致性缺口。公开 API 和 v4 wire format 不变，普通读取仍不扫描对象、校验内容或建立保留。

| 发现 | 修复行为 | 回归证据 |
| --- | --- | --- |
| 首次 current 失败留下空数据集目录，全仓治理被阻断 | 只有与初始固定请求匹配、没有历史和未知条目的空目录被视为未提交残留；其他缺失 current 仍拒绝 | 临时文件创建、replace 两处失败后，abandon→cleanup 成功，其他数据集仍可 GC；真实历史缺失 current 仍阻断 |
| GC 完成态重试漏同步 | 统一走控制验证及同步，再返回原始完成结果；完成不重选目标 | 在真实目录 fsync 处报错，恢复再次同步；protected 结果在释放引用后仍保留在同一计划中 |
| abandon 只同步放弃记录，依赖弱请求可能丢失 | 在不可逆放弃前同步 marker、request 及已有的 seal/protection/固定请求/对象权属证据，不同步数据字节 | writing、sealed、installed 三种候选验证同步顺序；同步失败不发布 tombstone、不解除复用保护；初始 protection 尚未创建也能放弃 |
| 每次 path/alias 都全量重建 FileSet | 会话内使用增量成员/对象/locator/祖先路径索引，缓存不可变 Store；seal 一次构建完整不可变清单 | 重复键、路径冲突、文件系统失败不污染成员；保护写失败不接受 reuse；多个别名仍共享一个对象 |
| 顶层未知控制条目被忽略 | 治理扫描检查控制根条目，未知文件或目录均阻断；规定格式的普通临时文件仍忽略 | 未知文件/目录及已完成 GC 的重试均拒绝；真实数据目录的未登记文件仍不获得删除权 |

[审计回归测试](../tests/test_audit_regressions.py) 的首批用例在旧实现上为 9 失败、1 通过，覆盖了全部审计问题；修复后再加入负向边界和失败原子性用例。

最终验证：新增 25 项审计回归用例，Python 3.11 和 3.12 全量测试各 535 项通过；Ruff、格式检查、Mypy 和全部示例通过。wheel、从 sdist 重建的 wheel 均通过隔离安装与可选 Polars 生命周期验证。独立审计代理复核五项修复，并完成 2,000 轮增量索引与 FileSet 的差分探针，未发现新的可操作缺陷。

[成员构建测量](../benchmarks/README.md#v4-候选成员构建) 覆盖 1,024–100,000 个成员，分别记录构建和不可变快照成本；不包含真实数据写入和提交吞吐。增量索引不会取消 seal 的闭包/路径完整验证。reuse 仍需要完整持久保护快照，不在此次优化承诺内。

GC 完成态重试现在会重新遍历、验证和同步控制证据，成本随控制历史增长；换取的是模糊失败后完整的持久化确认，不改变固定计划的对象范围。元数据压缩与更小的持久化依赖集仍属后续工作。

本轮故障注入与本地进程测试不构成真实断电或 NFS 资格。已公开暂缓的依赖图、Release/Pointer 等功能不随本次修复引入。
