# asterstore 0.2.0

本次发布增加显式治理诊断、单任务进度查询和 Polars 2.x 支持。普通读取仍直接使用已绑定文件路径，不自动检查数据、不隐式保留或刷新。

## 新增能力

- `governance.inspect()`：查看发布、候选、保留引用和维护任务，并解释对象为何受保护。
- `governance.check()`：显式检查元数据、文件存在性、调用方提供的格式校验，或基于可信 SHA-256 的内容一致性。检查只读，不修复、不删除。
- `collection_status()` / `cleanup_status()`：查询一个固定任务的进度，不扫描无关历史。
- 完成态 GC 重试仅核对原任务证据并重新同步完成记录；不重新删除对象。新 GC 和未完成恢复仍验证完整控制关系。
- 可选 Polars 支持 `>=1.32,<3`，兼容测试覆盖 Python 3.11/3.12 与 Polars 1.32.0、1.44.2、2.0.0。

## 安装与升级

```sh
uv add 'asterstore==0.2.0'
# 使用 Polars：
uv add 'asterstore[polars]==0.2.0'
```

磁盘格式保持 `format_version=1`，已有 0.1.0 仓库无需迁移；核心仍无第三方运行依赖。诊断类型从 `asterstore.governance.inspection` 导入。

诊断无法取得稳定观察时，四个接口统一抛 `RepositoryBusyError`。其他检查发现由 `check()` 汇总进报告，查询接口则抛出遇到的错误。registered 数据检查需显式提供资源映射；checksum 检查需调用方提供可信基准。Polars 自身的 schema/解码语义由引擎版本决定。

## 验证与范围

发行流程验证 Python 3.11/3.12 的测试、静态和协议检查、示例、基准 smoke，以及 wheel/sdist 重建后的隔离安装。CI 还下载真实构建制品，验证版本、文件名、大小和 SHA-256；PyPI 上传复用同次流程验证的制品。

不承诺首次 GC 提速。控制历史压缩、checkpoint/manifest 重构，以及读、写、运维治理进一步分离的设计仍由 [#21](https://github.com/Aequiludium/asterstore/issues/21) 跟踪，不属于本次交付。支持范围仍是本地 Linux/POSIX，不扩展为 NFS 写入或真实断电资格。
