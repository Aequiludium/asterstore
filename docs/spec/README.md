# asterstore 治理规范

状态：**目标规范草案 0.1，2026-09-25**。用于约束下一阶段设计与验收，不表示当前 Python API 或磁盘协议已经实现这些能力。本文编号不是仓库 `format_version`；当前可执行行为以 [API](../api.md)、[受管协议 v3](../protocol-v3.md) 和 [登记协议 v4](../protocol-v4.md) 为准。

asterstore 是面向文件数据的独立治理库。既有目录登记与库管理的发布是同等重要的接入方式。它管理声明、成员、管理权、引用和运维操作，不拥有业务解释权，不要求数据采用专有表格式。

## 设计优先级

**通用治理语义优先于旧 Aster 兼容。** 继承的原则是边界检查、轻量读取、有限且明确的保证、显式保留与可恢复运维；不继承旧 API、目录结构、JSON/pickle 分工、owner 定义或 GC 实现作为核心约束。

当旧实现与核心不变量冲突时，调整 Aster 侧适配器/应用，或提供显式导入与迁移；不得为保持旧行为增加核心特例。Aster 适配与生产迁移是独立的后续项目，不是通用核心交付或发布的前置条件。已有 asterstore 开发协议的读取支持是本轮具体行为，不代表必须永久兼容所有实验格式；格式演进必须显式拒绝不支持的记录，不能静默改义。

## 核心决定

1. 逻辑身份、逻辑成员、物理位置分开；发布 ID 不按路径校验，不按内容 hash 定义。
2. 原目录可只登记元数据，不复制数据、不改变现有生产者、默认无删除权。
3. 管理权、字节可变性、历史发现能力、保留范围和持久性分别声明；不再用单一 `physical_history` 推导全部保证。
4. 核心权威记录采用版本化、可独立解释的 JSON；业务附件可保留 JSON、pickle 或其他格式，核心不执行其解码器。
5. 普通绑定不产生保留。可变公开指针与固定任务保留分别表达，独立消费者拥有独立引用。
6. 来源记录与保留依赖分开。跨数据集依赖在同一协调域内显式声明，跨仓库自动保留不进入首版。
7. 闭合文件清单与确定性规则定位都支持；读取不扫描目录，不调用运行时业务日历推断已发布成员。
8. 不要求每次读文件做 exists/stat、schema 或 checksum 校验。内容 hash、内容寻址和去重均非默认要求。
9. 回收必须由管理权和完整保留关系证明，先持久计划与退役事实、再精确删除；未知对象不因未被引用而自动成为垃圾。
10. 开源交付包括语言独立的格式说明、能力矩阵、失败语义、兼容规则和可复现证据；不以功能数量代替这些约定。

## 本轮范围

规范后的首项实现已交付：v3 逻辑身份与物理路径分离、格式兼容门槛、Schema 与测试。没有升级既有仓库或迁移生产数据。另外已实现 Member/Object/Locator、FileSet、能力组合与显式资源绑定，见[声明模型](../declarations.md)。v4 已接入 registered 持久登记、身份核验与恢复，managed 创建权属、提交和恢复也已接入，直接保留/GC 已接入，依赖图仍待实现；其余目标概念仍不代表已导出的 API。

首个实现仍是 Python + uv，核心零第三方运行依赖，Linux 本地文件系统先验收。引擎通过 optional extras 接入；Aster 的业务桥接由 Aster 一侧维护，核心不得反向依赖 Aster。无提前引入的后台服务、插件发现系统、分布式锁服务或完整查询层。

## 当前实现差距

| 目标 | 当前事实 | 下一阶段要求 |
| --- | --- | --- |
| 不透明逻辑 ID | v3 已独立校验并保留来源 ID；控制路径使用 token | 扩展至后续 Store/Member/Release 模型 |
| 既有数据持久登记 | v4 已实现独立控制目录、registered 登记与恢复；不写外部文件 | managed 接入与资源配置演进 |
| 逻辑成员与定位分离 | 新声明已支持显式 Member → Object → Locator；旧 v3 仍是物理 ObjectRef.key | managed 持久接入及确定性布局 |
| 能力分解 | 新模型已分离管理方式、字节稳定性和历史发现；拒绝非法组合 | 接入持久权属、保留与 GC，不由声明标签授予权限 |
| 核心与业务元数据关联 | 暂无通用附件和版本关联 | 提交不可变关联，禁止业务字段暗中改变 GC |
| 多数据集公开选择 | 仅单数据集 current；任务引用固定目标 | 可选 Release 及条件公开指针，不承诺跨数据集数据事务 |
| 发布依赖保留 | 仅直接引用和同数据集共享对象 | 同仓声明/对象两层保留闭包 |
| 可恢复回收 | 已有固定计划、退役、恢复及候选清理 | 复用机制，扩展目标模型和权属检查 |
| 规模与部署 | 已有本地生命周期测试与小样本；尚未证明 NFS 写入资格 | 分开验证真实目录接入、治理规模、目标挂载 |

详细交付顺序见 [路线图](../roadmap.md)。
