# 一致性、成本与交付验收

## 1. 能力声明

每个实现/部署必须公布能力矩阵，至少区分 registered 绑定、managed 写入、公开 Release、依赖保留、物理 GC、共享挂载资格。功能可分阶段交付，不需要为只读用户启用全部能力。

报告应包括包/协议版本、Python/引擎版本、文件系统与挂载信息、操作范围、持久性、进程/客户端数、失败模型和未覆盖项。支持普通 NFS 读取不等于支持 NFS 上的写入与回收。

## 2. 必须通过的行为场景

| 编号 | 对应规范 | 验收场景与判定 |
| --- | --- | --- |
| A-01 | C-01, M-10 | 没有 Aster、Polars 的环境可导入核心、绑定声明并检查核心格式；optional extra 单独安装 |
| A-02 | C-02, C-03 | 来源 ID 含冒号/斜杠可往返保存；路径越界仍拒绝；不同 ID 不能因编码或归一化变成同一身份 |
| A-03 | C-04 | 控制根与数据根可分开；重绑定资源映射不会改变已有 Binding；只读数据挂载不因 bind 而写锁 |
| A-04 | C-05, C-07 | 登记一个持续原地更新的外部目录：登记不复制文件，不取得删除权；对象保留申请明确拒绝 |
| A-05 | C-05, C-06 | managed current_only 可用显式保留保护已选发布；外部 current_only 的 metadata 引用不能阻止外部覆盖，报告区别 |
| A-06 | C-08 | explicit 与 deterministic 在相同固定键域生成一致路径；新增目录文件不扩大旧 Binding |
| A-07 | C-08 | 稀疏日期集合保持固定；替换业务日历不改变绑定成员和 GC 范围；模板注入与碰撞拒绝 |
| A-08 | C-09 | 替换一个逻辑分区仅新增改变的文件；未变对象原路径复用；逻辑键重复或含糊替换失败 |
| A-09 | C-10 | 对 Binding.files 禁止 open/stat/lstat/scandir 等治理 I/O；普通读取不写引用、不续租、不刷新 |
| A-10 | C-10, C-11 | 缺失/损坏数据由原生引擎明确报错；空成员不会被当成缺失文件的自动修复 |
| A-11 | C-11 | 显式检查报告只宣称实际完成的层级；一次 checksum 检查不升级外部可变性的长期保证 |
| A-12 | C-12, M-07 | 同 generation 竞争提交只允许一个生效；其他候选可解释，不丢更新、不自动覆盖 |
| A-13 | C-12, M-07 | 在安装前、记录提交前、可见后响应前终止进程；重试同一操作不会二次切换或回退 current |
| A-14 | C-13 | Pointer 与固定 Retention 不同；两个消费者释放各自引用互不影响；旧 revision 不释放重建的新引用 |
| A-15 | C-13, C-14 | Release 切换时每次读到完整旧/新目标集合，不拼接各 dataset 当时 current；不宣称跨数据集生产事务 |
| A-16 | C-13, M-07 | 公开切换每个持久边界崩溃：新公开目标有保护；允许多余旧保留，禁止保护空窗 |
| A-17 | C-15, C-16 | provenance 不阻止回收；metadata 关系保留声明但可退役对象；objects 关系保护整个目标发布 |
| A-18 | C-16 | 多级依赖、重复边和环正确求闭包；无根环不自我保留；只有 metadata 根不递归保留所有字节 |
| A-19 | C-17, M-08 | 建立引用/依赖与 GC 竞争，只有“成功取得保护”或“目标不可用”的明确结果 |
| A-20 | C-18 | 混合 registered 与 managed：即使路径相邻，registered 数据与未知文件都不进入删除计划 |
| A-21 | C-18 | 预览后新增引用，执行重新计算；中断恢复不超出原计划，并跳过新保护对象 |
| A-22 | C-19, M-03 | 来源退役后共享对象可继续存在，最后引用释放后可回收；压缩不依赖永久保留原候选日志 |
| A-23 | M-01, M-02 | 不同应用编码均可作为不透明附件关联；核心治理只依据显式核心事实，不加载应用反序列化器。JSON/pickle 是可选样例 |
| A-24 | M-02, M-03 | fixed 附件与发布身份一致，公开失败不留下被当作成功的半关联；external evidence 明确较弱保证 |
| A-25 | M-04, M-05 | 重复 JSON 键、错误类型和未知治理功能拒绝；可忽略扩展保留且不改变 GC |
| A-26 | M-06 | 不支持的写入器/GC 拒绝新治理能力；普通 open 不迁移。若交付迁移工具，另验收重跑、备份和身份映射 |
| A-27 | C-19, M-07 | 压缩中断后恢复保持保留根、归属和退役事实；过期重试明确过期而非重新执行 |
| A-28 | M-08, M-09 | 对目标共享挂载进行跨客户端竞争、进程退出和服务故障验证；本地 SIGKILL 不替代服务器故障测试 |

旧行为模块继续承担已实现状态机的测试，不为每条规范机械新建一个测试文件。新模型先落在所属模块和共同 fixture 中；跨模块测试只覆盖真实关系与失败边界。

## 3. 成本契约

不以不受控的单次延迟设性能门槛。先验证调用边界，再记录规模曲线；有基线后才确定回归预算。

| 操作 | 不变量/需要记录的成本 |
| --- | --- |
| 单数据集 open | 只与该目标所需控制信息相关；不随不相关数据集/历史全仓扫描增长 |
| eager Binding 选择 | 零治理文件 I/O；explicit 选择通常与选择数相关；规则定位纯计算 |
| 增量写入 | 数据新增量与改变成员相关，不为未变成员复制、hash 或 resync |
| 声明提交 | 完整清单复制/编码成本必须披露；不能把少写数据等同于元数据零成本 |
| 保留建立与释放 | 记录控制读取量、写入量、锁等待；不预检数据内容 |
| GC/依赖遍历 | 记录数据集、发布、关系、候选、日志规模，以及控制扫描量和内存 |
| 删除与同步 | 与关系计算和锁等待分别报告，不用一个总耗时隐藏全仓 fsync 成本 |
| 压缩 | 输出记录数/字节、恢复成本、所需暂停时间；不改变可达性 |
| 引擎查询 | 相同数据、相同查询、相同选择，交替测量；计入原生 I/O，区分冷/热缓存 |

### 3.1 下一阶段测量计划

以下是测试输入目标，不是容量承诺：

- 成员规模：1、128、4096、25000、100000；先用元数据和小文件控制读取测试，不强制生成海量真实业务数据。
- 历史规模：同一数据集 1/100/1000 个发布，与 1/32/100 个数据集分别测量，避免不可执行的全笛卡尔组合。
- 引用与依赖：直接引用、长链和扇出分别构造；记录实际顶点/边数，并加入来自 retired source 的共享对象。
- 写入模式：单文件 full replace、日期追加、旧分区替换；记录数据文件新增量及完整清单增长。
- 真实目录：核心规模与布局验证使用独立可复现的文件数据集；Aster 32 表可作为后续接入样本，不作为核心验收门槛。其迁移报告的历史规模不冒充本轮全量统计。
- 部署：本地临时目录和指定目标挂载分别出报告；只读挂载只做读取验证。写入/删除/故障试验必须使用另建的隔离测试目录，不能以生产文件为故障注入材料。

每份报告记录源码版本或文件摘要、Python/引擎、CPU/线程数、介质/挂载、文件与压缩字节数、实际重复次数、缓存条件和负载限制。规模不足的样本只说明对应范围，不能宣称吞吐提升倍数或 NFS 资格。

## 4. 独立性验收

核心验收直接使用完全不依赖金融语义的示例，例如图像分片或模拟结果文件。Aster 是可选的后续适配案例，不是前置依赖：

1. 在原目录登记外部文件并绑定，不需要 Parquet/schema/交易日历。
2. 新受管发布复用未变成员，两个独立任务建立各自保留。
3. 一个任务只保留运行声明，另一个保留对象；回收行为与范围吻合。
4. 没有 Aster 的进程可以解释核心 JSON、打开受管数据和诊断失败操作。

若完成这些步骤仍需伪造 owner、factor、PIT 或 Aster publication 对象，则独立性验收失败。

## 5. 发布与阶段验收

每阶段的完成记录必须列出实现接口、持久记录、测试编号、已测环境和仍缺失能力。只增加文档不能把相应测试标为通过；仅测试通过也不能宣称格式已冻结。

首个规范实现版本冻结前：必须完成模型/格式评审、A-01 至对应已宣称能力的全部场景、零引擎核心安装与可选引擎安装验证，以及清晰的升级边界。A-28 是共享挂载写入/回收支持的单独门槛，不阻塞有限范围的本地版本发布。
