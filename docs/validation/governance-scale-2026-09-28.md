# 治理诊断与控制历史成本：2026-09-28

本次以实际 API 在临时仓库构建合成历史，未操作生产 AsterStore。
[索引前原始报告](governance-scale-2026-09-28-before.json)与[索引后原始报告](governance-scale-2026-09-28.json)保留所有样本、计数、峰值分配和源码 SHA-256。

索引前源码：[7844697](https://github.com/Aequiludium/asterstore/commit/7844697ebfa717cf2d662c49afdc24bdbc0fb7d7)；索引后源码：[bdb4ffd](https://github.com/Aequiludium/asterstore/commit/bdb4ffd7a64efc3d40bf001988a4195c835793cf)。两轮测量均通过测量前后源码一致性检查。最终归档再次校验索引后源码指纹。

## 条件与范围

- 本机 Linux x86_64、CPython 3.12、ext4 `/dev/sda2` 的 `/tmp`，单进程；不控制其他主机负载与 OS 缓存。
- 每次发布创建一个 128 字节的新对象，使用 durable 发布和治理；不包含大 Parquet 内容、复用关系或依赖图。
- 历史、数据集、引用和日志分别变化，另有 32 个数据集各 100 次发布的组合场景。
- 只读耗时是预热后三次样本的中位数，Python 峰值分配另行使用 tracemalloc 测量。GC 与完成态恢复只测一次且带探针；不能把它们当成吞吐量保证或 RSS。
- 锁计时不含并发争用；探针不是系统调用或物理磁盘 I/O 跟踪。元数据检查额外遍历使用 os.walk，其次数不在 Path.iterdir 计数中。

## 消除重复查找

基线代码每读取一条退役记录，都在线性回收计划中查找完整发布记录。同一大批次有 N 条退役记录时，会产生平方级重复比较。
现在为已验证的计划建立临时内存索引，按发布身份查找，再比较完整记录。磁盘格式、删除权属、恢复语义保持一致；没有持久索引或后台压缩。
新增回归测试限制一次治理预览中的 DeclarationRecord 比较次数随历史线性增长，不依赖运行时间阈值。

| 场景 | 回收后 preview：前 s | 后 s | 完成态恢复：前 s | 后 s |
| --- | ---: | ---: | ---: | ---: |
| 单表 100 次发布 | 0.092 | 0.150 | 0.251 | 0.394 |
| 单表 1,000 次发布 | 1.045 | 1.100 | 2.759 | 4.008 |
| 32 个数据集 × 100 次发布 | 4.146 | 3.878 | 10.413 | 11.209 |

两轮是同机顺序测量，缓存与负载未隔离，具体耗时差异只能作为本次观察；比较次数测试提供消除平方级路径的结构性证据。
治理仍读取全仓控制历史，完成态恢复仍需验证和同步证据。后续应扩大控制历史与对象复用规模，测量真实并发，再决定归档、压缩或进一步索引；本报告不提供生产容量上限或断电资格。
