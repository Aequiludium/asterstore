# Issue #21 D：实现、实测与复审交付

日期：2026-10-13。状态：D 本地实现及独立复审完成，尚未提交、推送或发布。

## 实现与设计收敛

交付 `governance.compact(operation_id, quiescent=True)`、两种严格协议记录、required_features=control_archive、原路径引用解析、固定计划恢复以及旧版本拒绝。完整契约见 [使用与协议](../control-compaction.md)，可执行 [示例](../../examples/archive_history.py)。

D2/D3 采用不可变内容地址 pack + 固定 checkpoint + 逐条等价原子替换，取代初稿的全仓指针切换。完整 current、对象身份、retention 保持独立。对象创建请求及 seal 的完整正文保存在不可变归档中，原候选路径保留身份引用；不能删除该身份目录或 writer.lock。压缩不删数据，不创建 TTL，不复用旧 ID，也不宣称已去掉全部逻辑创建者依赖。

D4 的首版选择落实为保留原有历史和重试语义，不引入有限窗口，也不实现 O(1) GC。对应代价是身份入口、归档和 checkpoint 继续增长。后续若要清除历史身份或减少文件数，必须另立协议，不能通过删除本版引用达成。

现有未完成任务保守阻止压缩；维护窗口要求停止写入、治理和历史查询，已有 writer 句柄额外由非阻塞锁拒绝。checkpoint 前失败可以重新规划且保留遗留 pack；checkpoint 后按固定范围恢复。无正向收益时不修改 marker。

## 可复现实测

```bash
uv run --locked python benchmarks/control_compaction.py > /tmp/control-compaction.json
```

[脚本](../../benchmarks/control_compaction.py)与[原始结果](issue-21-d-2026-10-13.json)。四组独立临时仓库，每次发布创建新对象，每对象 9 字节；准备发布采用 durable=False，GC 和压缩遵守各自强同步协议。脚本固定 store/dataset/publication/operation 身份，对象 ID 由运行时 UUID 生成，因此各次压缩长度可能有小幅差异；保存 Python/平台、运行时与脚本 SHA-256，并验证运行前后源码一致。

计量为 `.asterstore` 下文件逻辑长度，不含 managed-data、锁文件、目录块及文件系统分配单元；包括 marker、checkpoint 和 pack。正式测量串行完成，无测试/另一个基准并发；缓存不驱逐。延迟为同一仓库压缩前/后各 5 次顺序调用的中位数，不代表冷缓存、负载隔离或生产性能。

| 发布数 × 每发布对象数 | 状态 | 压缩前字节 | 压缩后字节 | 实际减少 | 文件数前→后 | 压缩耗时 |

- 全套 395 项测试通过，其中 D 新增 29 项。覆盖历史声明/读取、managed 与 registered 重试、跨归档 reuse、GC、retention、cleanup、身份冲突及弱→强恢复。
