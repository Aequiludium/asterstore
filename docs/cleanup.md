# 数据集维护清理

`repo.clean(dataset_id, quiescent=True, dry_run=True)` 查看当次候选统计；去掉 dry_run 执行重新计算后的清理。预览不保存可稍后执行的计划。

调用方须停止目标数据集的新读写任务，等待旧 Binding 及延迟计算最后一次 I/O 结束，并保持窗口到清理完成。修改锁排除 writer，不登记或阻止 reader。不同数据集可继续工作。

清理保留 current 和 rollback 的全部成员（包括业务元数据），删除其他对象、过期版本清单及失败 staging。它预检整个目标子树，不跟随软链接；任何目录扫描错误都会原样抛出，预览和实际清理都不会返回不完整的成功结果，实际清理也不会提前开始删除。保留清单损坏、文件缺失或未知控制文件导致停止；没有 head 的目录跳过，不猜测它是首次失败还是 head 丢失。

删除前同步保留状态。若删除中途报错，下次重算即可，不需恢复日志。删除文件不会同步每个 unlink；机器故障后少量垃圾可能重新出现，下次再清理，不影响已同步的保留版本。

旧 Binding 在维护窗口之后不应继续使用，必须重新 open。清理不是备份，也不负责整数据集销毁。
