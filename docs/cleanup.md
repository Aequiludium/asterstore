# 维护清理

清理保留 current 和 rollback 引用的全部文件，删除目标数据集中的其他对象、过期版本清单和失败 staging。业务元数据也是普通成员，会随其所属版本保留。

## 执行步骤

1. 停止目标数据集的新读写任务。
2. 等待已有读取完成，包括 Binding 派生的延迟计算。
3. 保持维护窗口，预览或执行清理。
4. 清理结束后恢复任务，消费者重新 open。

```python
preview = repo.clean("prices", quiescent=True, dry_run=True)
result = repo.clean("prices", quiescent=True)
```

`quiescent=True` 表示调用方已完成协调，不会阻止读者进入。修改锁排除同一数据集的 writer，但读取不取锁。其他数据集可以继续工作，只要它们的任务没有读取清理目标。

dry_run 只返回当次统计，不保存删除计划；实际执行会重新计算。统计包含数据文件、清单和 staging，不只计算业务文件字节。

## 失败处理

删除前完整预检目标子树和保留集合，再同步保留状态。目录扫描失败、保留清单损坏、文件缺失、软链接、特殊文件或未知控制文件都会阻止删除开始。

删除中途遇到 I/O 错误时可能已经清理部分垃圾。解决故障后重新调用 clean 即可，不需要恢复删除日志。删除本身不逐次同步，机器故障后少量垃圾可能重新出现，可再次清理。

没有 head 的目录会跳过，不能据此推断其中内容全部可删。这也意味着首次发布前失败的目录不会由 clean 自动回收；应单独核实该目录状态后处理。

## 调度

清理周期决定过期文件和失败产物的峰值空间。两次清理之间可以多次发布；仅推进 current/rollback 不会立即回收文件。

清理会使更早版本不可读。维护窗口之后不得继续使用旧 Binding。清理不是整数据集删除，也不是备份操作。
