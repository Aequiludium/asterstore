# 双版本架构

AsterStore 只负责一个数据集内部的文件成员、原子发布、一次回退和静默维护清理。它不理解更新频率、业务检查、schema、日期或任务批次。

核心分为模型/codec、文件原语、Repository 读取、单次 Draft、cleanup。无数据库、引用图、对象注册表、永久事务日志、历史增量链或读者租约。

允许每次发布写完整清单，成本 O(成员数)。正式保留数量最多为二；清理成本 O(目标数据集物理文件数 + 保留成员数)，不扫描其他数据集。清理之间遗留仍会增长，因此验收区分峰值和稳态。

普通文件成员可承载业务元数据；受限相对路径可承载引擎的分区后缀。这两项能力不要求核心理解 Aster。下游迁移和生产切换不属于新核心的独立实现验收。

详见[协议](protocol.md)、[API](api.md)和[设计讨论记录](plans/dataset-two-version-protocol.md)。实现行为以 API 和协议文档为准。
