# 设计原则与规范入口

2026-09-25 起，目标设计由 [治理规范草案 0.1](spec/README.md) 统一组织。它取代此前把长期目标和实现进度混在一起的设计叙述；当前 API 与磁盘协议仍分别以 [api.md](api.md) 及 [受管 v3 协议](protocol-v3.md)、[登记 v4 协议](protocol-v4.md) 为准。目标规范不是对旧仓库记录的隐式重新解释。

asterstore 是面向文件数据的独立治理库。库管理的不可变对象发布与既有目录登记都是主要接入方式。它负责声明、成员、管理权、引用和运维，保持读取路径轻量，不承担业务数据解释或查询引擎职责。

## 长期原则

- 管理权、不可变性、历史访问、保留和持久性分别说明；current_only 是可接受的使用方式。
- 逻辑身份、逻辑成员与物理位置分开；不强制内容寻址、全量复制或每读校验。
- 绑定固定声明，普通文件定位不自动刷新、加 pin、续租或执行检查。
- 既有目录可以只登记，不因此赋予删除权、并发控制或快照保证。
- 通用治理事实有独立、可解释的协议；应用 JSON/pickle 元数据可继续存在并固定关联。
- 来源记录与保留依赖分开，公开指针与任务引用分开，退役与实际删除分开。
- 失败、恢复、版本演进和测量方法属于库的公开契约。
