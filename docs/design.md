# 架构与边界

数据集是一个独占目录。更新是该目录内明确的一组文件替换与删除，加上一份调用方发布元数据。行情日期、factor 定义版本等只是调用方路径与元数据，不引入不同的存储模式。

## 最小核心

- Repository 只登记数据集目录；目录重叠在登记时拒绝。
- Dataset 维护一个当前记录、一份有效撤销材料和至多一个活动安装/恢复记录。
- Batch 生成本次文件，在发布前保存本次修改的旧文件，安装后提交当前记录。
- clean 删除失效工作材料，不计算文件可达性，不删除正式数据。

核心范围是目录内的文件变更、当前状态和一次回退。初始化只接受空目录。

## 一致性

数据集写锁串行化准备、安装、回退、恢复和清理。调用方负责在安装、回退和恢复期间停读，等待在途延迟读取完成。current 只检查当时的活动记录并读取小型元数据，不锁定未来的文件访问。

数据变化通过日志恢复，而非多文件瞬时原子切换。发布前失败恢复旧数据并保留原有回退机会；提交后异常依据 head 的操作身份保留新数据。主动回退消耗回退机会，不能来回切换。

无事务的外部写入、跨数据集文件共享、外部替换目录不在协议范围。不同注册仓库不能竞争初始化同一目录树。

## 成本

更新 K 个文件时，记录、校验和同步只涉及 K 个文件及相关目录。备份量取决于本次被替换或删除文件的字节数。正式历史数据量不会增加一次小更新的管理遍历。

新发布成功前，上一份撤销材料与本次候选、备份可能同时存在。旧材料在显式 clean 时移除；全量重算应准备足够空间。

操作回退不取代灾备；进程故障测试不证明实际硬件断电行为。无永久历史读取、读者租约或跨数据集原子发布。
