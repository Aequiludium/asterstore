# 保留与回收：场景推演及验收规格

状态：2026-09-24 的设计验收规格，**不是所有场景都已实现通过**。引用、revision 重试、多进程协调、v1/v2 门槛和控制元数据预览及共享对象保护已有测试；退役、实际删除及回收恢复也已覆盖下述本地故障场景；断电和共享挂载资格尚未验证。对应 [保留设计](retention.md)。下文简写对象键为 a/b/c，实际文件键仍需满足受管路径规则。

## 1. 两个消费者、共享文件和回收

初始发布与对象：

```text
P1(generation=1) = {a, b}
P2(generation=2) = {b, c}    # current
引用 task-A → P1
引用 task-B → P1
策略 keep_last=1
```

| 操作 | 拟退役发布 | 可回收对象 | 必须成立的解释 |
| --- | --- | --- | --- |
| 预览 | 空 | 空 | P1 被两个引用保护，P2 是 current |
| 释放 task-A 后预览 | 空 | 空 | task-B 独立保护 P1 |
| 再释放 task-B 后预览 | P1 | a | b 仍属于 P2，不能删除 |
| 执行回收 | P1 变为 retired | 只处理 a | 即使 a/b 位于同一创建候选目录，也不能 rmtree |
| 旧候选重试 P1 | 不重新发布 | 无 | 返回已退役错误，current 仍是 P2 |

预览的对象并集计算可以在没有真实文件的情况下验证；实际共享文件删除已有本地文件系统测试；不由纯集合测试推导。

## 2. 预览后新增保护

1. P1 无引用，P2 是 current，预览给出 P1/a 可回收。
2. 消费者为 versioned 的 P1 建立引用并成功返回。
3. 运维调用 collect，传入同一策略。
4. collect 重新计算，保留 P1/a；旧预览不会成为强制删除列表。

若 GC 先拿到独占锁并退役 P1，之后消费者建立引用必须失败。两种顺序都不允许“返回保留成功，但 GC 仍依据旧关系删除”。current_only 不能在 P1 已变旧后新建此引用；该例的历史选择前提必须在测试中明确。

## 3. current_only 的显式保护

1. P1 为 current；retain(name, dataset) 在数据集锁内选择 P1 并返回绑定。
2. 生产者提交 P2；P1 的独立文件仍被 active 引用保护。
3. 普通 open(dataset, publication_id=P1) 仍拒绝历史能力。
4. retention.open(name, expected_revision=1) 返回已保留的 P1。
5. 释放引用后，原绑定不再阻止 GC；读取成功与否取决于对象是否仍存在。

该场景只适用于遵守新路径写入约定的受管对象。外部程序原地覆盖文件不能通过引用获得同样的保证。

## 4. 引用请求结果不确定与名字复用

| 时点 | 动作 | 持久状态 | 预期 |
| --- | --- | --- | --- |
| 1 | retain，expected_revision=0，选择 current=P1 | active/1 → P1 | 若成功响应丢失，可以重试 |
| 2 | current 切到 P2，重试同一创建请求 | active/1 → P1 | 返回 P1，不重新选择 P2 |
| 3 | release，expected_revision=1 | released/2 → P1 | 引用不再保护 P1 |
| 4 | 重试 release/1 | released/2 → P1 | 幂等识别并按需补同步 |
| 5 | retain，expected_revision=2，选择 P2 | active/3 → P2 | 同名引用得到新 revision |
| 6 | 旧任务再次 release/1 或 retain/0 | active/3 → P2 | 明确冲突，不影响 P2 |

名字的 released 记录不能直接删除，否则第 5 步可能从 revision=1 重新开始，使第 6 步误操作新引用。

## 5. 回收逐阶段中断

| 中断点 | 留下的事实 | 恢复行为 |
| --- | --- | --- |
| 计划落盘前 | 没有退役、没有删除 | 无删除任务需要恢复，重新预览 |
| 计划已落盘，尚未退役 | 已知原操作范围 | 重新检查根；后来被引用保护的目标跳过 |
| 只退役了部分目标 | 部分发布已不可新建引用 | 不回滚退役；剩余目标重新判断，再进入删除 |
| 退役记录替换后同步失败 | 退役可能已可见，持久性未确认 | 停止删除，恢复先同步所有必要事实 |
| 已全部退役，尚未删除 | 身份和计划完整，文件仍可能存在 | 按原计划减去当前可达对象 |
| 删除部分文件，进度记录尚未更新 | 部分对象已不存在 | 不存在且不再被使用者视作已处理；继续同步与剩余删除 |
| 完成响应丢失 | 完成记录或足够的状态证据 | 返回/重建结果，不重新引入已退役发布 |

一个操作未完成时，新的 collect 要求先恢复原操作。普通发布和引用服务可以运行，但必须识别已经发生的退役。

## 6. 候选保护与来源退役

```text
P1 = {a, b}
P2 = {b, c}，current
封存且未提交的候选 C = {a, d}
无具名引用，keep_last=1
```

P1 可以退役，但 a 仍被 C 保护，b 被 P2 保护，因而 P1 当前没有可删除对象。C 的原 generation 是否允许提交与其对象是否仍被保护是两件事；冲突候选在显式放弃前仍保留。

C 恢复时使用自己的封存成员关系，不要求已退役的 P1 再变成可用发布。相反，新候选不能从已退役 P1 任意重新引入 a；必须通过另一个有效来源或明确引用选择。来源信息不会自动成为永久保留依赖。

## 7. 必须覆盖的实现验收项

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| R01 | 独立名字保护同一发布 | 释放一个不影响另一个 |
| R02 | 创建/释放响应丢失 | 同一 revision 重试可识别；持久重试补同步 |
| R03 | 名字释放后重建 | 旧请求冲突，不发生 revision 归零 |
| R04 | 原子选中 current 并保留 | 并发提交前后只选择完整的一个发布 |
| R05 | current_only 受管发布 | 新建引用只选 current，已有引用可重开目标 |
| R06 | 冲突、已退役或不存在目标 | 不写入 active 引用，不伪造保护成功 |
| R07 | 外部已丢失文件 | retain 不做健康审计；显式审计/实际读取报告缺失 |
| G01 | 元数据预览 | 不打开、stat 或枚举数据对象目录，不退役、不删除 |
| G02 | 共享对象 | 只有全部使用关系消失才可删除 |
| G03 | 范围只选一个数据集 | 仍考虑全仓其他声明；不删除范围外发布 |
| G04 | 预览后新增引用 | collect 重新计算并保留新目标 |
| G05 | 保留与 GC 竞争 | 引用成功受到保护，或退役先发生而引用失败 |
| G06 | 活跃/封存/冲突候选 | 活跃会话阻止 GC；封存对象受保护；不按年龄猜测 |
| G07 | 已提交候选残留 | 不是额外永久保留根 |
| G08 | 控制记录损坏或关系缺失 | 预览 blocked，执行不开始删除 |
| G09 | 未声明文件、未知目录和锁文件 | 不按目录整体删除，不跟随符号链接 |
| G10 | weak durability 之后 GC | 删除前同步 current/引用/候选等控制依据和目录；同步失败停止 |
| G11 | 退役与 unlink 之间任意中断 | 有持久计划可恢复，退役不复活 |
| G12 | 进度记录落后于 unlink | 恢复能判断缺失对象，不因过期进度扩大删除范围 |
| G13 | 中断后新增引用/发布 | 恢复只处理原范围且重新排除受到保护的对象 |
| G14 | 旧提交身份重试 | 区分已提交可用与已退役；新候选不能重用旧发布 ID |
| F01 | v1/v2/v3 混用 | 旧写入器拒绝 v3，新治理写入入口拒绝 v1/v2；读取保留各版本语义 |
| F02 | 等锁前检查版本的旧进程 | 不将单独取得锁宣称为在线升级安全证据 |
| P01 | 普通读取成本 | current 打开不扫描引用/历史；绑定后的路径选择无文件 I/O |
| P02 | 运维成本 | 单独记录锁等待、控制文件数量与对象集合内存，不宣称零成本 |

每一项实现时先选择其所属测试模块和真实故障模型，再加入必要测试。文档推演、集合计算和本地进程测试分别说明证据范围；不得写成断电或共享挂载验证通过。
