# 发布、回退与恢复

一个数据集的一次更新通过 `with dataset.write(expected_revision=...) as batch` 完成。用 stage 写完整候选文件，用 delete 声明删除。调用方检查候选内容后，进入读取维护窗口，再 commit 元数据。

## 更新五天

假设已有数据到 10 月 10 日，本次更新 8—12 日：stage 五个分区文件；提交备份 8—10 日，记录 11—12 日原来不存在，再安装五个文件，提交可用日期等元数据。其他历史日期不动。

回退恢复前三天、删除后两天、恢复原元数据。下一次成功发布后，这份旧备份可以由 clean 删除；五天正式数据不会因 clean 被删除。见[可运行示例](../examples/transactions.py)。

增量行合并由调用方完成，核心只接收完整文件替换，不理解证券主键或修订优先级。

## Factor

追加到 `version=v1/date=.../data.parquet` 与行情新增相同。同定义重算备份并替换明确日期。换定义时写入 v2 路径并更新元数据，回退撤销本次新增路径并恢复 v1 身份。

旧定义目录不是垃圾，clean 不删除。退役定义需要显式 delete 对应文件，形成一批可回退的删除。历史发布元数据不保证历史文件内容永久可读。

## 异常

准备阶段失败且尚未安装时，退出上下文丢弃暂存；进程直接退出留下的孤立准备目录由 clean 处理。安装开始后失败保留 active 与备份，current 和 clean 拒绝继续。

保持读取停止，调用 `recover(quiescent=True)`。未提交的安装撤销，已提交的安装保留新数据，进行中的主动回退继续完成。恢复可重复调用；不能凭异常类型判断提交是否发生。

第一次发布可回退到未发布状态。纯元数据更新也可撤销。无文件变更且元数据相同是 no-op，不增加 revision，不消耗回退机会。
