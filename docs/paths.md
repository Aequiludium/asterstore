# 文件路径与归属

数据文件不必位于控制目录内。Repository 的 root 定位控制元数据；文件清单记录仓库相对路径或仓库外绝对路径。绝对路径绑定具体存储位置，移动控制目录不会重新定位外部文件。

## 接管已有文件

`draft.adopt(key, path)` 把现有普通文件加入草稿。文件不复制、不移动、不新增硬链接，seal 后 Binding 返回同一真实路径。相对路径以 root 为基准；目录别名解析为真实目录，文件本身不能是软链接。

接管意味着转交清理权限。调用方必须确认文件可独占归属该数据集，关闭写入器，并停止其他应用对其修改。同一个仓库内禁止两个数据集接管同一路径，也不能通过文件硬链接绕过约束；跨仓库独占归属由调用方保证。

接管记录在 seal 写入版本清单时生效，commit 再切换正式版本。业务检查失败或 seal 后续步骤失败，也可能留下已接管但未发布的文件；维护清理可删除这些文件。只有 preflight 失败且尚未写入清单时，文件仍未交接。

## 指定新文件路径

`draft.allocate(key, path=...)` 独占创建一个空文件并返回准确路径；调用方在该路径写入。它不会覆盖已有路径，也不会在 seal 时搬动该文件。自定义路径可与控制目录位于不同文件系统。

省略 path 时，allocate 在仓库 staging 中提供路径，seal 安装到默认 objects 目录；relative_path 仅决定此默认布局内的后缀。指定 path 时不要再用 relative_path 指定位置。

新自定义路径文件在 seal 记录前不属于仓库清理集合：进程提前退出、成员被移除或 preflight 失败时，调用方负责处理文件。默认 staging 中的中间产物仍可由仓库清理。

## 清理和并发

不扫描外部目录，也不根据路径前缀认领文件。所有尚未清理的版本清单构成接管集合，current/rollback 构成保留集合；差集中的文件才可以回收。外部目录中的其他文件及空目录保持原样。

为拒绝跨数据集重复接管，自定义路径预留、seal 与 clean 使用仓库归属锁协调清单访问。clean 的锁持续到删除结束。它不是跨数据集发布事务；head 切换仍独立。读取不取得此锁。

归属检查会读取仓库中的版本清单，成本与尚存清单的成员总数有关，不扫描其他数据集的数据内容。定期清理保持清单规模受限。不建立逐文件注册表或永久操作日志。

删除外部文件后先同步其父目录，再删除过期清单并同步版本清单目录。只有最后的目录同步完成，归属撤销才算持久生效。该步骤失败时清单可能已经不可见；重试 clean 会补齐同步，自定义路径预留及包含自定义路径的 seal 也会在归属锁内先同步各版本清单目录，避免未持久的旧归属在断电后复活。清理仍要求调用方协调维护窗口。

仓库控制文件及其后代路径、整个 `.asterstore/datasets` 子树都不能作为自定义数据位置，包括当前数据集的默认 objects 目录。默认目录中的成员通过普通 allocate、reuse_current 和 alias 管理。路径不接受父级越界段；记录中的路径必须规范，封存后的数据路径不得替换成软链接或其他文件。
