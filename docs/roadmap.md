# 下一步与验收

当前只有一种格式和生命周期实现，仍处于开发阶段。先验证真实应用，再冻结首版 API。

1. 选择一个实际数据集接入：登记已有文件或受管写入，通过原生引擎读取，完成增量复用、固定保留、释放和回收。
2. 在该应用的实际更新节奏、目录规模和并发方式下验证操作身份、generation、恢复成本和轻量读路径；以应用反馈简化接口。
3. 根据接入证据确定首版必要功能与保证范围，再做 API/格式冻结和发行。当前行为与边界见 [API](api.md) 和[首版范围](release-scope.md)。

发布依赖图、Release/Pointer、deterministic 布局、业务附件、元数据压缩、完整审计和共享挂载资格仍未交付。不以预先列出这些概念作为首版实现义务；后续由实际需求决定顺序。

Aster 可以作为首个应用，但业务 PIT、字段质量、调度和历史目录适配属于应用侧。核心保留轻量读取、显式治理、固定计划和可恢复操作；不兼容旧 Aster 或本项目开发草稿。
