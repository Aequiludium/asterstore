# 下一步与验收

v0.1.0 已发布到 PyPI 和 GitHub。后续迭代保持单一磁盘格式、显式治理和轻量读取。

本轮新增（尚未发版）：治理状态快照、对象保护原因解释、显式只读检查。接口与覆盖范围见[诊断与检查](inspection.md)。

1. 在实际更新负载中记录历史、数据集、引用、回收日志规模与发布/治理成本。持续增加规模，保存环境、缓存条件与原始报告。
2. 根据测量结果决定是否需要控制记录归档、压缩或索引；必须保留恢复与删除权属证据。
3. 单独设计并演练整库备份与恢复，明确复制期间的对象保护和恢复验收。

跨数据集发布组合、发布依赖图和共享挂载资格由实际需求决定。下游项目自行决定使用固定 Git 提交或 PyPI 版本；Aster 的集成与生产切换在其项目内推进。

PIT、字段质量、交易日、数据库同步与调度属于应用侧。核心不识别具体表，不引入后台运维服务。
