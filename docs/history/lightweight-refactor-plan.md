# 轻量存储重构设计记录

状态：历史设计记录，保留需求、取舍和验证依据，不作为当前操作指南。实现已进入工作树；当前行为以 [API](../api.md)、[磁盘协议](../protocol.md) 和 [架构](../design.md) 为准。

更新日期：2026-10-15。

方案制定时只新增文档，后续已获授权进行代码重构。用户计划清理既有数据后重新开始，因此切换采用重新初始化、重新生产数据，不开发旧协议转换工具，不保留旧 API 兼容层。本文不授权或执行任何数据删除。

## 1. 目标与取舍

用一套轻量文件管理核心覆盖行情日更、历史修订、factor 追加与重算：

- 每个数据集独立发布，日常读取最新数据。
- 业务检查在正式安装前完成；发布成功后，可以撤销最近一次成功发布。
- 按本次变更处理文件，不为一次日更重建所有历史分区的清单。
- 保留自然的 Hive 目录，路径由调用方配置。
- 不提供永久发布历史、任意历史数据读取、跨数据集事务、读者租约或依赖图 GC。
- 核心只管理普通文件与发布元数据，不解释 Parquet、交易日历、因子定义、schema 或 lineage。

关键取舍：正式文件允许被替换，因此不再提供并发发布期间的不可变读取快照。安装、回退、异常恢复期间，调用方必须暂停该数据集的新读取，并等待已有读取真正完成，包括延迟计算的最后一次文件访问。仅修改发布指针不能让多个文件替换同时可见。

这项读取协调是方案的部署前提。暂存和业务检查期间仍可读取旧数据；不同数据集不要求一起停读。未完成事务恢复前不能开放受影响数据集。

## 2. 统一的数据模型

一个数据集绑定一个独占的数据目录和少量控制记录。目录位置可配置；不同数据集的数据目录不能相同或互相包含。绑定时校验目录边界，而不是每次发布扫描全仓库的文件归属。

```text
行情目录/
  date=2026-10-13/data.parquet
  date=2026-10-14/data.parquet

因子目录/
  version=v1/date=2026-10-13/data.parquet
  version=v1/date=2026-10-14/data.parquet
  version=v2/date=2026-10-14/data.parquet
```

这些是布局示例，核心不强制日期层级、文件名或每个分区只有一个文件。调用方提交相对于数据集目录的明确文件路径。一个多文件分区的替换必须列出要新增、替换、删除的文件；核心不推断分区内哪些文件已经过期。

同一数据集的临时文件和撤销材料放在数据集所在文件系统的隐藏控制目录，避免正式安装依赖跨文件系统 rename。正式读取必须使用明确的数据文件模式，排除控制目录，不能递归读取隐藏备份。

核心保留路径越界、控制目录访问、软链接及非普通文件检查。目录绑定后不允许绕过存储层修改文件；不支持通过硬链接别名跨数据集共享可变文件。不建立任意外部文件接管或归属转移协议。

### 发布元数据

当前发布记录只保存：操作序号、当前发布身份、调用方元数据、可空的撤销材料引用。文件格式与最终 API 名称留待实现确定。

- 行情可以保存可用日期、修订范围等。
- factor 可以保存当前定义版本、覆盖范围、必要的输入身份等。
- 核心把这些内容作为不透明元数据，与文件变更一起提交和恢复。
- 历史 lineage、业务审计和研究 pin 不纳入核心保留机制；元数据存在不等于历史数据可读。

factor 定义版本与发布批次不同。同一个 `version=v1` 可以经过很多次追加或重算，不必每次产生一个全量存储快照。

## 3. 最小控制状态

| 状态 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前发布记录 | 当前身份、元数据、操作序号、撤销材料引用 | 一份 |
| 活动事务 | 本次修改路径、原存在状态、旧文件备份、原发布记录、新文件暂存 | 每个数据集最多一份 |
| 上次发布的撤销材料 | 撤销最近一次成功发布所需的旧文件及元数据 | 一份 |
| 数据集写锁 | 串行化发布、回退、恢复和清理 | 一个 |

活动事务与上一份撤销材料在新发布成功前可以同时存在。不能为了保持“只有一份备份”提前删除上一份，否则新发布失败会丢失原有回退能力。

未修改文件留在正式目录，不需要记录为复用成员。没有版本对象目录、逐文件全局归属表或永久事务历史。

## 4. 发布流程

一次提交包含明确的替换列表、删除列表和新发布元数据。重复或互相冲突的路径必须拒绝；调用方根据旧数据构造候选时，使用预期操作序号检测过期状态。

1. 取得数据集写锁，处理未完成事务并检查预期序号。首版采用同一写锁覆盖准备到提交，避免引入多个并行候选协议。
2. 将本次完整的新文件写入 staging，完成业务检查。正式数据尚未改变，读者可以继续读。
3. 调用方进入安装维护窗口，停止新读取并等待在途读取结束。
4. 对本次替换、删除的已有文件复制备份；对新增文件记录“原来不存在”。保存原发布元数据。新文件、备份和必要目录同步成功后，持久化事务记录。
5. 逐文件安装或删除。新文件通过同文件系统的临时路径原子替换，完成必要的持久化同步。
6. 原子替换当前发布记录：发布新身份与元数据，并将本次撤销材料设为回退来源。该记录的持久化完成是成功判定依据。
7. 清除活动事务标记，淘汰更早的撤销材料，恢复读取。收尾失败不能把已经提交的发布错误地当作未提交而撤销。

不能通过一个事后写入的“已成功”日志单独判断是否提交；恢复必须核对当前发布记录中的事务身份。响应丢失或提交报错时，读取该记录并执行恢复流程确认状态，不能盲目重放安装。

不引入独立 seal、可永久保留候选、并行 Draft 或恢复计算任务的 API。事务恢复只负责恢复文件状态，不续跑业务计算。

## 5. 五天增量更新示例

当前行情到 10 月 10 日，本次更新 10 月 8—12 日，五天一起发布：

| 日期 | 原状态 | 发布操作 | 撤销材料 |
| --- | --- | --- | --- |
| 10 月 8 日 | 存在 | 替换 | 原文件 |
| 10 月 9 日 | 存在 | 替换 | 原文件 |
| 10 月 10 日 | 存在 | 替换 | 原文件 |
| 10 月 11 日 | 不存在 | 新增 | 原不存在记录 |
| 10 月 12 日 | 不存在 | 新增 | 原不存在记录 |

先生成五个完整分区文件并检查；在维护窗口内备份前三天，安装五天，最后更新发布元数据至 10 月 12 日。其他历史分区不访问、不复制、不同步。

- 安装中途失败：恢复前三天的旧文件，移除本次已经安装的后两天文件，恢复原发布记录。此前的回退材料仍有效。
- 成功后主动回退：执行相同的数据恢复，整批退回发布前状态，消耗本次回退机会。
- 下一次成功发布：本次三份旧文件备份成为可清理材料；五天正式数据不因清理而删除。

如果数据源给的是五天内的部分行，调用方先合并旧分区与增量，形成每天完整的新文件。按证券代码去重、修订优先级、行合并不属于存储核心。

## 6. 其他典型操作

| 场景 | 发布 | 回退 | 清理 |
| --- | --- | --- | --- |
| 行情日更 | 安装新增日期文件，更新元数据 | 删除新增文件，恢复元数据 | 淘汰失效撤销记录 |
| 历史修订两天 | 备份并替换两天文件 | 恢复两天旧文件与元数据 | 后续发布成功后删除旧备份 |
| factor 追加 | 向当前定义目录新增日期文件 | 删除新增文件，恢复覆盖范围等 | 与行情日更相同 |
| factor 同定义重算十天 | 备份并替换十天文件 | 恢复十天旧文件与元数据 | 淘汰失效的十天备份 |
| factor 换定义 | 安装新定义文件，切换元数据中的定义身份 | 撤销本次变更，恢复原定义身份 | 不自动删除旧定义目录 |
| 显式删除数据 | 先备份指定文件，再删除 | 恢复被删除文件 | 回退机会淘汰后才删备份 |

旧因子定义不是事务垃圾。不再作为当前定义，并不授权 clean 删除它。退役定义需调用方明确列出要删除的文件，作为独立发布处理。核心不分析依赖图，也不根据“当前未引用”自动删除正式数据。

纯元数据更新也可以是一次发布，保存原元数据作为撤销材料；完全无变更的请求应作为 no-op，不消耗现有回退机会。

首次发布也可撤销：删除本次新增文件，恢复“尚未发布”的状态。初始化前已存在且未经登记的数据不允许被隐式接管或覆盖。

## 7. 回退与故障恢复

主动回退在维护窗口内执行，并先持久化回退意图。恢复旧文件时从备份复制到临时文件再替换，不消耗源备份；删除原来不存在的路径要可重复执行。

恢复完成后写入新的操作序号和旧业务状态，清空回退引用。回退不提供 redo，也不恢复更早一轮回退机会。只有提交回退结果后，相关备份才能清理。

| 中断位置 | 恢复规则 |
| --- | --- |
| 暂存或备份阶段，未开始安装 | 正式数据不变，丢弃本次未完成准备 |
| 已持久化安装意图，但当前发布记录未指向本次事务 | 恢复发布前文件及元数据，保留此前回退材料 |
| 当前发布记录已指向本次事务 | 保留新数据及本次撤销材料，完成收尾 |
| 主动回退已开始、尚未提交结果 | 重复执行恢复步骤，直到完成回退 |
| 回退结果已提交 | 保留回退后的数据，继续清理残留 |
| 清理中断 | 已提交状态不变，下次继续清理明确的失效材料 |

备份缺失、记录损坏或状态无法判定时应停止开放该数据集并报告错误，不能猜测成功或把记录直接删除。进程故障注入不等同于真实断电证明；持久化顺序和部署文件系统语义需分别验证。

## 8. 清理与成本

clean 取得数据集写锁，只删除已确认失效的 staging、已完成事务残留和被淘汰的撤销材料。当前发布引用的撤销材料及活动事务不能删除。正式数据删除必须是显式发布操作。

清理不遍历历史数据、不扫描其他数据集、不计算可达性。仅删除控制范围内自己创建的空目录；删除新增数据后的空 Hive 目录可保留，不为了目录整洁扩大清理范围。

设本次变更文件数为 K、变更数据量为 B：

- 本次事务记录与路径校验规模为 O(K)，不依赖历史文件总数。
- 新数据写入、旧数据备份与同步成本取决于 B。
- 提交前峰值包含正式数据、上一份撤销材料、本次 staging、本次旧文件备份。
- 全量重算可能需要接近一份旧数据的备份空间；这是一次回退的实际成本，不用硬链接或隐式共享掩盖。
- 目录扫描读取的成本仍由读取引擎和分区裁剪决定；本方案只承诺发布管理不全量遍历。

## 9. 保留、删除与替换

| 当前能力或机制 | 决定 | 目标实现 |
| --- | --- | --- |
| 数据集独立管理、零第三方核心依赖 | 保留 | 文件与控制记录管理 |
| 数据集写锁、预期 revision 校验 | 保留 | 串行修改和过期请求检测 |
| 安全路径、普通文件检查 | 保留 | 仅检查目录边界及本次路径 |
| 原子控制记录、必要 fsync | 保留 | 只同步本次文件及相关控制状态 |
| 一次回退 | 保留，改实现 | 差量撤销材料 |
| 暂存、发布前检查 | 保留，简化 | 候选文件完成后一次提交 |
| 全量版本 manifest、Member 文件列表 | 删除 | 本次变更日志 |
| objects UUID 布局、不可变文件版本 | 删除 | 自然路径上的文件替换 |
| Binding 固定文件集合 | 删除 | 当前目录及发布元数据，明确维护窗口 |
| reuse_current | 删除 | 未修改文件自然保留 |
| 任意单文件 adopt、跨路径归属转移 | 删除 | 数据集目录绑定 |
| 全局 ownership.lock、全仓库 _claims | 删除 | 初始化或绑定时的目录冲突校验 |
| current/rollback 可达性 GC | 删除 | 明确事务材料清理 |
| seal 独立生命周期 | 删除 | 单次准备与提交流程 |
| 提交时同步全部保留文件 | 删除 | 本次变化同步 |
| 必须通过 manifest 文件列表读取的适配 | 删除或重写 | 自然路径读取；不解释业务 schema |
| 跨数据集事务、历史版本 pin、lineage GC | 不引入 | 超出核心范围 |

旧协议 Schema、旧 API 测试、旧快照示例和旧规模基准随实现替换，不保留双协议分支。路径安全、原子写入和文件同步工具可按新语义复用，但不能为了复用旧模块继续保留旧概念。

## 10. 切换方案：清空后重建

用户已决定清理既有数据后重新开始。取消原位转换、硬链接迁移、旧 manifest 导入及旧 rollback 转换；不实现兼容读取或自动升级旧目录。

### 阶段 A：确认契约

固定目录独占范围、读取维护窗口、一次回退语义、因子定义目录规则及不支持的历史能力。明确无外部直接写入。文件格式与 API 只实现上述最小能力，不预先加入扩展框架。

### 阶段 B：隔离实现与验收

在临时目录实现核心；以合成行情和 factor 数据完成下节验证。先验证故障恢复和变更规模，再完成文档、示例和发行验证。不连接生产目录运行破坏性测试。

### 阶段 C：部署准备

盘点要初始化的数据集目录和控制目录，列明实际路径；停止旧写入、旧清理任务及读者，防止旧版本在新目录继续操作。清空数据由用户另行执行，本文不执行删除。既有未发布文件不能被新初始化静默接管。

调用方只需接入批量文件变更、发布元数据及维护窗口；不要求本项目实现业务计算、业务质量规则或调度系统。

### 阶段 D：重新初始化和首次生产

确认目标数据和控制目录符合空目录初始化要求后，建立新格式标记与数据集绑定。旧格式存在时明确拒绝，不自动改写。重新生产数据，经检查完成首次发布，再开放读取；随后验证一次日更、一次修订和一次回退。

本次是重建，不保留清空前的数据回退能力。首次新发布的回退只能恢复未发布状态；第二次成功发布后才具备退回首次发布数据的能力。

### 阶段 E：收尾

验收通过后停用旧客户端入口、旧协议工具、旧文档和旧定时清理任务。新协议出现问题时停止开放、完成恢复或重新初始化重建，不得让旧版本客户端直接操作新目录。切换失败恢复依赖重新生产，不宣称可以还原已经清空的旧数据。

## 11. 验证计划与通过标准

| 类别 | 必测内容 | 通过标准 |
| --- | --- | --- |
| 基本发布 | 新增、替换、删除、混合变更、元数据更新、首次发布 | 文件内容与发布元数据一致；未修改文件不变 |
| 五天增量 | 三天替换加两天新增 | 成功后五天正确；回退恢复三天并移除两天 |
| 行情与 factor | 日更、历史修订、追加、同定义重算、换定义 | 共用核心；定义身份与发布批次独立 |
| 一次回退 | 连续三次发布、失败发布、主动回退、首次发布回退 | 只撤销最近一次成功发布；失败不损坏原回退能力 |
| 故障注入 | 备份、写日志、每次安装/删除、提交记录前后、回退、清理 | 每个中断点恢复到已定义状态；恢复重复执行结果一致 |
| 模糊提交结果 | 原子替换后异常、同步失败、返回前进程终止 | 核对事务身份，不盲目重做或撤销已提交发布 |
| 路径安全 | 越界、目录重叠、软链接、控制路径、非法文件、重复操作 | 修改前拒绝，不碰其他数据集或控制文件 |
| 并发与窗口 | 同数据集冲突、不同数据集独立、过期序号、恢复前读取 | 修改串行；过期请求拒绝；调用方演练覆盖延迟读取结束 |
| 清理 | 活动事务、有效备份、失效材料、清理中断 | 只删除失效材料，不触碰正式数据或有效回退 |
| 空间失败 | 备份或安装空间不足、权限错误 | 未提交变更可恢复；此前回退材料保留 |
| 读取 | 自然 Hive 路径、控制目录排除、多文件分区 | 不读备份和 staging；不依赖完整成员清单 |
| 新部署 | 空目录初始化、旧格式拒绝、全新安装与示例 | 无旧协议隐式转换，包外安装可运行 |

规模验证使用合成的 100、1,000、10,000 个历史分区，在每档规模下更新相同的五个分区。记录文件访问数、目录遍历、同步次数、控制记录字节数及耗时：

- 发布、回退不得遍历所有正式分区或其他数据集。
- 发布记录不包含全部历史路径；事务记录只包含五个分区涉及的文件。
- 不同步未变更的历史文件。
- clean 访问范围只在明确的控制材料内。
- 时延只作辅助证据，不能用某次耗时较短代替操作规模验证。

实现阶段需完成新的语义回归、静态检查、协议检查、构建和源码外安装验证。文档阶段只检查链接、差异和方案一致性，不声称上述测试已通过。

## 12. 实施顺序

1. 实现目录绑定、最小控制记录与数据集锁。
2. 实现变更事务、安装和失败恢复，先通过故障注入。
3. 实现一次回退与失效材料清理，覆盖连续发布和中断回退。
4. 用行情及 factor 示例验证同一核心，再做规模验证。
5. 删除旧快照、归属和 GC 实现，替换协议、API、测试和正式文档。
6. 完成隔离安装验收后，再进入清空重建部署流程。

当前的 [架构文档](../design.md)、[磁盘协议](../protocol.md) 和 [API](../api.md) 已随工作树实现更新。旧发行版不能使用新协议；尚未进行生产清理、重建或部署。

实施细化：旧撤销材料在成功发布后成为可清理材料，由显式 clean 删除，不在提交返回前自动清理。prepare 阶段崩溃的孤立工作目录也由 clean 处理；有活动安装记录时必须先显式 recover，再恢复读取或开始下一次写入。
